# Changelog

All notable changes to Kernova will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Project

- Releases are published from GitHub Actions ([`release.yml`](.github/workflows/release.yml)) with npm trusted publishing, so every package has a provenance attestation and no npm token is stored anywhere. `scripts/publish.mjs` publishes the packages whose version isn't on npm yet, in dependency order; `scripts/release-notes.mjs` turns a `CHANGELOG.md` section into the GitHub release notes
- Added [`GOVERNANCE.md`](GOVERNANCE.md), [`ROADMAP.md`](ROADMAP.md), and [`.github/CODEOWNERS`](.github/CODEOWNERS). Contributions are licensed under MIT, like the project

## [2.0.1] — 2026-11-04

Releases: `@kernova/framework` 2.0.1, `@kernova/cli` 1.2.1.

### Security

- **The agent server listened on every network interface** in `kernova dev`, and in `kernova start` behind a Next.js app, without authentication, so anyone on the same network could call your agents and their tools. It now listens on `127.0.0.1` in those setups (the app forwards to it on localhost); set `KERNOVA_HOST` to change that. An agents-only `kernova start` still listens on all interfaces

### Fixed

- **`kernova dev` didn't start the agent server** on current versions of tsx (`node: bad option: --ignore`), and still printed "Agent backend running". It now uses `tsx watch --exclude …`, reports "running" only once the server answers `/health`, and says so when it fails to start. `tsx` is now a dependency of `@kernova/cli`, so the first `kernova dev` no longer downloads it
- Tools never received `ctx.threadId` or `ctx.user`, although the tool context documented them
- A trigger's `enabled: false` had no effect
- `kernova dev` printed a health URL that answered 404, and didn't accept quoted values in `.env.local`

### Added

- Tools get `ctx.autonomous` (`true` for trigger and schedule runs), `ctx.trigger`, and `ctx.agent`, so a tool can ask more of actions nobody asked for; `currentRequest()` returns the same from any code a request runs
- `when` on triggers: checked each time a trigger would fire; returning `false` skips the run before any model call
- `KERNOVA_HOST` sets the address the agent server listens on

## [2.0.0] — 2026-11-03

Releases: `@kernova/core` 2.0.0, `@kernova/sdk` 2.0.0, `@kernova/framework` 2.0.0, `@kernova/types` 1.1.0, `@kernova/cli` 1.2.0, `create-kernova-app` 1.3.0, `kernova` 1.0.0 (first release).

### Breaking

- **Node.js 22 or newer is now required** (`engines.node: ">=22.0.0"`). Node.js 20 reached end-of-life in April 2026. Docker images generated by `kernova deploy docker` now use `node:24-alpine`.
- **Unsafe built-in tools are off by default.** `shell-exec`, `code-eval`, `file-read`, `file-write`, and `database-query` are only available when listed in `builtInTools.enabled` (for example `enabled: [...DEFAULT_BUILT_IN_TOOLS, 'shell-exec']`). `database-query` also needs an explicit `databasePath`; it no longer defaults to the kernel's own database
- **The file-tool sandbox moved** from `<dataDir>` to `<dataDir>/workspace`, so file tools can't reach `kernova.db`
- **`web-search` is only offered when `builtInTools.webSearchProvider` is set.** It previously always returned no results
- **The gateway requires authentication.** `kernel.gateway.start()` throws unless `auth.tokens` (or `KERNOVA_API_KEY`) is set or `auth.allowAnonymous` is true. It now listens on `127.0.0.1` instead of `0.0.0.0` and sends no CORS headers unless `cors` lists origins (or is `true`)
- **Webhook routes with a `secret` always verify signatures**, using the `x-kernova-signature` header when `transform.signatureHeader` isn't set
- **Self-reflection is off by default** (`KernelConfig.reflection.enabled` defaults to `false`). It added at least one extra model call to every answer
- **Agents no longer share one conversation.** History is kept per `metadata.threadId` (`app.ask(goal, { threadId })`); intents without a thread are independent
- **Default models updated:** Anthropic `claude-sonnet-5-5`, Gemini `gemini-flash-latest`, Groq/Together `openai/gpt-oss-120b`, Fireworks `gpt-oss-120b`, Cerebras `gpt-oss-120b`, SambaNova `Meta-Llama-3.3-70B-Instruct`, Cohere `command-a-03-2025`, xAI `grok-4-latest`, Perplexity `sonar`. Several previous defaults have been retired by their providers
- `GeminiProvider.id` is now `'gemini'` (was `'custom'`)
- Persisted events older than 30 days are deleted at start and daily. Set `eventRetentionDays: 0` to keep them forever
- **Agents use their own model settings.** An agent definition's first `models` entry (provider and/or model) and its `config.temperature` / `config.maxTokens` are now sent with its model calls; they were ignored. The provider must be registered
- Providers passed in `KernelConfig.providers` replace auto-detected providers with the same ID (an auto-detected provider used to override yours)
- `DaemonRunner.start()` starts the kernel if it isn't running, and `port` now serves the gateway (which needs a token)
- `kernova studio` talks to the gateway through its own server, which adds the token (`--token` or `KERNOVA_API_KEY`), and listens on `127.0.0.1` only
- The development dashboard (`StudioServer`, started by `kernova dev`) no longer sends CORS headers and refuses cross-origin requests
- **Framework:** `defineConfig()` no longer sets a default `model` (it was `openai/gpt-4o`); without one, the first provider with an API key is used. `middleware/` files, agent `budget`, agent `model` / `temperature` / `maxTokens`, and `gateway.rateLimit` now take effect (none of them did). The framework kernel keeps no thread history of its own (`threadHistory: false`). On `SIGINT` / `SIGTERM` the server now shuts everything down and exits
- **Channel adapters verify inbound requests:** WhatsApp needs `appSecret` to receive messages; Teams requires a valid Bot Framework token; SMS and Voice require a valid `X-Twilio-Signature` (set `webhookUrl` behind a proxy); Telegram webhooks require the secret token the adapter registers. `WebhookChannelAdapter` and `WebSocketChannelAdapter` listen on `127.0.0.1` unless `secret` / `token` (or `host`) is set, and WebSocket browser connections need a listed origin or the token
- **Replies go to an explicit recipient.** `send(message, recipient)` takes an inbound message's `replyTo`. Without one, adapters use their configured default or the only conversation they've seen; with several active conversations they return an error instead of sending to whoever wrote last. `WebSocketChannelAdapter.send()` with a recipient reaches only that client
- **Framework:** self-reflection is off unless `reflection` is set in `kernova.config.ts` or on an agent (it graded nearly every answer with an extra model call). `defineAgent()` no longer fills in `temperature: 0.7`, `maxTokens: 4096`, or `middleware: []`
- `@kernova/core` now uses better-sqlite3 13 (N-API; prebuilt binaries ship in the package) and cron-parser 5
- **Azure OpenAI and Bedrock have real providers.** The `azure_openai` and `bedrock` catalog entries were placeholders that couldn't work (OpenAI format against `{resource}` URLs). Azure OpenAI's provider ID is now `azure` (`azure_openai` still works as an alias); see Added
- Audio and file parts sent to a provider that can't take them raise an error naming the provider and the input. They were sent as text such as `[audio: https://...]` (OpenAI-compatible, Anthropic) or dropped (Ollama, which also dropped image URLs)
- For subclasses: `OpenAICompatibleProvider.requestHeaders()` is now async, and URLs come from `endpoint(path, model)`; `GeminiProvider`'s settings are `protected` and its URLs come from the async `modelUrl()` and `authHeaders()`

### Security

- `code-eval` could escape its sandbox and run arbitrary code on the host (`Object.constructor('return process')()`). It now runs in a separate Node process under the permission model, with no host objects, an empty environment, a memory cap, and a hard kill on timeout
- `file-read` and `file-write` accepted paths in sibling directories that share the sandbox's name prefix (`../workspace-private/...`) and followed links out of the sandbox. Both are now rejected
- `shell-exec` passed the whole host environment, including API keys, to commands. Commands now get a minimal environment plus `builtInTools.shellEnv`
- `http-fetch` could reach localhost, private networks, and cloud metadata (`169.254.169.254`). Those addresses are blocked by default (including on redirects), and response bodies are capped
- The gateway was open to anyone who could reach the port, and to any web page via CORS `*`. See Breaking above. Token comparison is now constant-time
- Webhook signatures were checked against a re-serialized body (so real signatures failed) with a non-constant-time comparison, and a secret without `signatureHeader` skipped verification
- The tool-calling loop ran any registered tool the model named, even ones not offered to it
- The Postgres memory and conversation stores logged stored user content to stdout
- `SignalAdapter` built a shell command from message text, so a reply containing `$(...)` ran on the host. It now runs `signal-cli` without a shell. (The channel adapters are now exported, see Added)
- The development dashboard (`StudioServer`) sent `Access-Control-Allow-Origin: *` without authentication, so any web page open in the developer's browser could create API keys, read them, and submit intents
- The Studio page built into the CLI inserted memory contents, event messages, and logs as HTML (stored XSS); values are now escaped
- **Framework:** `middleware/` files never ran, so endpoints the authentication guide protected with middleware were open. `gateway.rateLimit` never limited anything (the rate limiter was constructed with the wrong arguments)
- Studio's Next.js is now 16.4.4; `npm audit --omit=dev` reports no vulnerabilities
- **Channel adapters accepted forged requests.** Teams trusted any posted activity and then sent the bot's access token to the activity's `serviceUrl`; SMS and Voice accepted any caller (a forged request could make the bot place calls on your Twilio account); WhatsApp messages, Telegram webhooks, and the generic webhook and WebSocket adapters had no checks at all. Each now verifies the platform's signature or token (see Breaking), and request bodies are capped at 1 MB
- The Email adapter didn't escape lines starting with `.`, so a reply could end the message and inject SMTP commands (sending mail anywhere through the bot's account). The IRC adapter let a `\r` in a reply inject IRC commands. Both are fixed, and recipients are validated
- Browsers don't apply CORS to WebSockets, so any web page could connect to a WebSocket channel; connections from browser origins are now refused unless listed in `allowedOrigins` or authenticated with `token`

It exits with code 1 when no provider works

### Fixed

- **Anthropic tool calling failed** on the request after any tool call: the assistant's `tool_use` blocks weren't sent back, so the API rejected the `tool_result`. Parallel tool results are now grouped into one message, and all system messages are sent (only the first was)
- **Only OpenAI and Anthropic keys worked out of the box.** With any other auto-detected provider, every request asked for a model literally named `"default"`. The kernel now uses each provider's own default model (and `OPENAI_MODEL` is respected)
- Gemini tool results were named after the call ID instead of the function; thought signatures are now returned with function calls; tool schemas use `parametersJsonSchema` (the old field rejected `additionalProperties` and `default`, used by the built-in tools); the API key is sent in a header instead of the URL; embeddings use `gemini-embedding-001`
- OpenAI: reasoning models (`gpt-5`, `o*`) rejected `temperature`, `stop`, and `max_tokens`; streamed responses never reported token usage; malformed tool arguments failed the whole response
- Local OpenAI-compatible servers (LM Studio, vLLM, llama.cpp) were unusable because they were treated as unavailable without an API key, and declared embedding support was ignored
- Cohere pointed at its native API instead of its OpenAI-compatible endpoint
- `ModelRouter.embed()` failed if the first provider couldn't embed instead of trying the next one; routing overrides were ignored for agent and vision calls (`metadata.purpose`)
- Documents ingested into `kernel.rag` were retrieved but never given to the agent
- `KernelConfig.toolPolicy` and the tool policy engine had no effect on what agents could call; MCP tools were never available to agents despite the docs. Connected MCP servers' tools are now registered as plugin tools
- Submitting with an `owner` that isn't a registered identity failed with "Permission denied". Unregistered owners are now treated as labels; registered identities still need `intent:submit`
- All requests without an owner shared one 100-requests-per-minute limit, including the kernel's own sub-agents and schedules. The internal `system` owner is now only limited by an explicit rule
- Budgets charged concurrent intents for each other's tokens; usage is now measured per intent, including reflection
- Reflection with no `threshold` set rewrote every answer (an undefined threshold replaced the default), and an unparseable grade triggered rewrites. `defineAgent({ reflection })` was ignored, and a per-agent `enabled: true` didn't apply when reflection was globally off
- `kernel.stop()` left the identity database open (the data folder stayed locked on Windows) and didn't wait for active intents; it now refuses new intents and waits up to `shutdownTimeoutMs`
- `shell-exec` timeouts killed only the shell on Windows, leaving the command running; the whole process tree is now killed. The model can no longer raise the configured timeouts of `shell-exec`, `code-eval`, or `http-fetch`
- `regex-match` couldn't stop catastrophic backtracking and froze the process; patterns now run in a worker thread with a hard timeout
- An async infinite loop in `code-eval` hung the host process
- The library printed debug lines to stdout on every request (agent logs, tool lists, OpenAI responses). Agent `log()` output now goes to events, and to the console only with `debug: true`
- `@kernova/core/gateway` and `@kernova/core/daemon` imports in the docs didn't resolve; they're imported from `@kernova/core`
- **Framework apps sent conversation history twice** (and the prompt grew every turn) once the kernel kept thread history; the framework keeps its own
- `kernova serve` never started the kernel (every intent failed with "Kernel is not running"), ignored `--port`, and printed "Daemon is running" only after shutdown
- `app.channel()` never connected its adapter, so SDK webhook and WebSocket channels never listened
- Projects from `kernova init` didn't run (`kernovaKernel` import, agent never registered) and installed `@kernova/core` 0.1.x
- `kernova status` always reported the daemon as "Unknown" (wrong column), missed `src/agents/` and `.agent.yaml` when counting agents, and saw no heartbeat for the first 60 seconds (the daemon now sends one at start)
- `kernova deploy docker` wrote a Dockerfile that failed for core projects and left out framework folders such as `tools/`, `middleware/`, and `skills/`
- `${VAR}` references in `.kernova/mcp.json` were passed to MCP servers literally
- A `measureUsage()` scope nested in another counted only toward the inner one
- The SDK `agent()` helper dropped `reflection` and `toolPolicy`; daemon agent config files ignored `model`
- Approval events used an invalid severity (`warning`)
- **Messages received through `kernel.channels` went nowhere:** the registry had no way to register a handler
- Every channel adapter replied to whoever wrote last, and `WebSocketChannelAdapter.send()` broadcast each reply to every connected client
- Slack messages were dropped as invalid (Slack's `ts` was used as the timestamp)
- Telegram replies with unbalanced Markdown were rejected (they're now resent as plain text), and long-polling retried in a tight loop while the network was down
- The Teams adapter's access token expired after an hour and was never refreshed
- Framework agents created with `defineAgent()` got `middleware: []`, so no middleware ran for them
- `getNextCronDate()` returned a meaningless date for an invalid reference date; it now throws
- `jsonMode` was ignored by every provider; it now asks for JSON (`response_format`, `responseMimeType`, Ollama's `format`, or an instruction for Claude)
- Mistral and Cohere embeddings asked for OpenAI's `text-embedding-3-small`; they now use `mistral-embed` and `embed-v4.0`
- Ollama streams lost tool calls and the length stop reason, and the "Ollama is not running" hint never appeared (Node's fetch reports the refused connection in `cause`)
- Gemini prompts blocked by its safety filters (`promptFeedback`), answers stopped for recitation or prohibited content, and Claude refusals were reported as a normal stop; they now finish with `error`
- Simulated streaming (providers without `stream()`) dropped tool calls from the final chunk
- API errors now show the provider's error message instead of the whole response body
- **Scheduled jobs due more than about 24.8 days out ran immediately** (Node fires longer `setTimeout` delays after 1 ms), and a cron job such as a yearly report then ran again and again. The same limit made approvals with long timeouts expire at once, background loops with long intervals run constantly, and framework triggers such as `schedule.30d` fire every millisecond. All of them now wait the full time
- `OPENAI_BASE_URL`, `OPENAI_MODEL`, `ANTHROPIC_BASE_URL`, and `OLLAMA_HOST` were ignored when the provider was auto-detected (the catalog's defaults took precedence), so requests went to the default endpoint and model

- **`ephemeral: true` now keeps every store in memory.** The scheduler, background loops, task queue, and triggers previously wrote to `./kernova-data/kernova.db` even in ephemeral mode
- The scheduler no longer hangs on startup when a frequent job has been offline for a long time. Missed-run reporting is capped at 100 events per job, and the last one is marked `truncated: true`
- `kernova studio` crashed with `__dirname is not defined`
- `kernova studio` could serve files outside its asset folder through `..` paths. Requests outside the folder now get `403`
- `kernova --version` always printed `0.1.0`. It now reports the installed version
- `kernova --help` now lists every command (`create`, `build`, `start`, `login`, `logout`, `studio`, `doctor` were missing)
- `PluginRegistry.executeTool()` and `getTool()` accept the original tool ID (`math:add`) as well as the sanitized one (`math_add`)
- `PluginRegistry.unregister()` now removes the plugin's tools. They were previously left behind
- Published packages no longer include compiled test files. Builds start from a clean `dist/`, and `prepublishOnly` rebuilds before publishing

## [0.2.0] — 2025-07-10

### Added

- **Daemon Mode**
  - `kernova serve` CLI command for persistent agent execution
  - `app.serve(options)` SDK method to start a DaemonRunner
  - Graceful shutdown with configurable timeout (default: 30s)
  - Heartbeat emission (`daemon.heartbeat` event) at configurable intervals

- **Scheduler Enhancement**
  - One-shot delayed jobs via `delayMs` field on `ScheduledJobInput`
  - `app.schedule(name, cronOrDelay, handler)` SDK method (accepts cron string or delay in ms)

- **Task Queue Enhancement**
  - Configurable concurrency limit (default: 5) with worker pool
  - Priority-ordered dequeue (critical > high > medium > low), FIFO within same level
  - `app.enqueue(handler, payload, options)` SDK method

- **Channel System**
  - `ChannelAdapter` interface with `connect()`, `disconnect()`, `send()`, `onMessage()` methods
  - `WebhookChannelAdapter` — HTTP POST receiver with configurable port and path
  - `WebSocketChannelAdapter` — WS server with ping/pong keepalive (30s interval)
  - `app.channel(name, adapter)` and `app.onMessage(handler)` SDK methods

- **Conversation Threads**
  - Sliding window with summarization (oldest messages summarized when exceeding window size)
  - `app.thread(threadId)` SDK method returning a `ThreadHandle` with `addMessage()` and `getContext()`

- **Agent Planning**
  - Plan-and-execute pattern with `plan.step.started` and `plan.step.completed` events
  - Replanning on step failure (invokes model to replan remaining steps with error context)
  - `maxSteps` limit (default: 10) to prevent unbounded plan execution
  - `app.plan(goal, options)` SDK method

- **Agent Config Files**
  - YAML/JSON declarative agent definitions (`.agent.yaml`, `.agent.yml`, `.agent.json`)
  - `extends` field for config inheritance (merge base + child configs)
  - Hot-reload when `--watch` flag is set on `kernova serve`
  - `kernova init` now generates a starter `.agent.yaml` file

- **Built-in Tools**
  - `http-fetch` — HTTP requests with configurable method, headers, body
  - `file-read` — read file contents within sandbox directory
  - `file-write` — write content to files within sandbox directory
  - `shell-exec` — execute shell commands with timeout (default: 30s) within sandbox
  - `date-time` — current date, time, timezone, and formatted strings
  - `web-search` — web search with configurable provider (stub/adapter pattern)
  - Sandbox enforcement for file and shell tools (path traversal rejected)
  - Per-tool enable/disable configuration via `KernelConfig`

- **Self-Reflection**
  - Configurable confidence threshold (default: 0.7) — regenerates response if score is below
  - Max regeneration limit (default: 2) to prevent infinite loops
  - `reflection.regenerated` event with original and new confidence scores
  - Per-agent and global configuration for enabling/disabling reflection

- **Proactive Triggers**
  - Event-driven rule engine with SQLite persistence
  - Cooldown enforcement — rules cannot fire more than once per `cooldownMs` period
  - `app.trigger(name, eventPattern, action)` SDK method

- **CLI Commands**
  - `kernova serve` — persistent daemon with `--config`, `--watch`, `--port`, `--data-dir` options
  - `kernova schedule list|enable|disable` — scheduler management
  - `kernova queue status|replay` — task queue management
